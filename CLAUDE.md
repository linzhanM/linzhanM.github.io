# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

This is a personal academic homepage for Linzhan Mou, deployed as a GitHub Pages static site at the custom domain `linzhanmou.com`. There is no build system, no package manager, and no server-side code — the one build step in the repo is the LaTeX résumé (see `resources/resume/`).

**Domain**: the root `CNAME` holds `linzhanmou.com`. Five hostnames — `www`, both `http` variants, and `linzhanm.github.io` — each single-hop 301 to it with the path preserved, so old links keep working. `linzhanmou.com` is the only host that serves content. **Every absolute self-link must use it** (`index.html`, `publications.html`, `resume.html`, `dimo/`, `unimate/`, `sitemap.xml`, `robots.txt`, `resources/resume/resume.tex`), otherwise internal navigation pays for a redundant DNS+TLS handshake (~2× the load time). Don't delete `CNAME` — it is the switch for the whole redirect setup.

## Development

To preview locally, serve the directory with any static file server:

```bash
python3 -m http.server 8000
# then open http://localhost:8000
```

To deploy, commit changes and push to `main` — GitHub Pages serves the branch automatically, usually live within ~1–2 minutes. `main` **is** the deploy branch, so a feature branch does not deploy.

There is no Git LFS setup and no `.gitattributes` — all media is committed directly (videos, images, PDFs, `.glb` models). GitHub Pages cannot set response headers here, so anything header-based (HSTS, `X-Robots-Tag`) is not available; `robots.txt` and `<meta>` tags are the only levers.

Five pages, in two groups. `index.html`, `publications.html` and `resume.html` sit side by side at the root and **share** `styles.css` + `custom-navbar.css` + `nav.js`, and the navbar markup itself (so a token change reaches all three); `dimo/` and `unimate/` are fully independent and share nothing with them or with each other. `resources/resume/` holds the built PDF, its LaTeX source, and its build tool; there is no separate `latex/` directory.

## Architecture

**No framework**: no templating, routing, or JS framework anywhere. Every page is hand-written HTML.

**CSS hybrid** (homepage + résumé): local stylesheets layered on a CDN-loaded Bootstrap 4 **CSS** grid (no Bootstrap/jQuery JS — neither page loads any). `css/custom-navbar.css` owns *all* navbar chrome: the sticky bar, the mobile burger, the ≥1024px flex layout, the `.nav-section` eyebrow labels, and the `.nav-keypoint` accent dot. `css/styles.css` holds the design system: a `:root` block of design tokens, base typography, and the hero / section / publication / experience / footer styles. Fonts are Fraunces (display — name and section headers) and Source Serif 4 (body), from Google Fonts; `.pub-title` overrides to Palatino Linotype. The homepage's third-party loads are exactly: Bootstrap 4 CSS, Font Awesome 5 (`.fab`/`.fas` icons in `.hero-links`), Academicons (`.ai-google-scholar`), Google Fonts, StatCounter, and four `img.shields.io` GitHub-star badges — nothing else. The star counts are **plain `<img>` badges**, which is why the old `buttons.github.io/buttons.js` was removed: it acts only on `class="github-button"` elements, and shields.io had already replaced it. Don't re-add a script for star counts. `resume.html` deliberately drops the two icon stylesheets, because its contact links say "Scholar"/"GitHub" in words and the icons were labelling what was already labelled.

The `:root` tokens are a system, not a loose bag — stay on them rather than hard-coding a value:
- **Surfaces** `--ivory-light/-medium/-dark`, `--accent-bg`.
- **Ink, four tiers** `--text-primary/-secondary/-tertiary`, each documented with its contrast ratio (all ≥4.5:1 AA on `--ivory-light`).
- **Radius, three steps** `--radius-sm/-md/-lg`, all fixed px on purpose — percentages resolve against the box and turn non-square elements into shape-shifting ellipses. A circle (the nav keypoint) is a shape, not a step, and stays `50%`.
- **Elevation, two layers each** `--shadow-plate` / `--shadow-lift` — a tight contact shadow plus a diffuse ambient one, so media reads as set *onto* paper rather than floating.
- **Accent** `--accent: #E77500` (Princeton orange) is for **geometry only** — rules, borders, the keypoint, link underlines. Never the colour of running text: orange dark enough to pass AA on ivory is orange gone brown.

Three rules to keep in mind when editing CSS here:
- `styles.css` loads **after** `custom-navbar.css`, so a `.navbar` rule placed in `styles.css` silently wins. Keep navbar rules in `custom-navbar.css`. `styles.css` currently has none — verify before adding.
- `css/resume.css` touches the navbar in exactly one place — `@media print` hides it. It used to re-declare `.navbar-inner` and add a `.resume-nav-links` group, because the résumé page ran a two-link nav of its own; both were deleted when the page took the site navbar unchanged. Don't reintroduce a per-page navbar layer: the two pages now share the same markup, so a difference between them is a bug, not a variant.
- Bootstrap defines `.navbar` as `display: flex` with `padding: 0.5rem 1rem`; `custom-navbar.css` zeroes that padding and gives `.navbar-inner` `width: 100%` so it doesn't collapse to its content. Don't remove either without re-checking the layout.

**Cache busting**: the local `<link>`/`<script>` tags carry a `?v=N` query, because GitHub Pages caches aggressively. **`styles.css`, `custom-navbar.css` and `nav.js` are referenced from three files — `index.html`, `publications.html` and `resume.html` — so bump `N` in ALL THREE** whenever you edit any of them, or returning visitors keep the old file. Keep the three files' numbers **equal** for a given asset: same file at the same URL means one shared cache entry instead of three fetches. `nav.js` and `styles.css` are at `v=42` and `custom-navbar.css` at `v=39`, each matching across the three pages; they had drifted to 37/34 once, which left the résumé page serving a stale `styles.css`. `resume.css` (`v=12`) and `publications.css` (`v=1`) are each loaded by one page only and carry their own counters. `dimo/` carries no `?v=` at all. `unimate/` versions **everything local**: both HTML files version their CSS and JS entry points, and every ES-module import between the viewer files carries its own `?v=` (entry module → `viewer.js` → `examples.js` → `showcase.js`, plus the helper imports), because a stale ES module is not merely styled wrong, it is a broken viewer. When editing a unimate file, bump the `?v=` at each import site and walk the bump up the chain to the HTML — `unimate/README.md` documents the scheme.

**Styling convention**: `index.html` and `resume.html` carry **no inline `style=` attributes and no `<br>` spacers** — every rule lives in a stylesheet behind a named class (`.hero*`, `.page-section`, `.exp-*`, `.resume-*`, `.site-footer`). Both files are currently at zero of each; keep it that way. Sections are `<section class="container page-section">`: the Bootstrap `.container` is required, because `.row` uses −15px side margins that need the container's padding to cancel them.

**JavaScript** (homepage + résumé):
- `js/nav.js` — loaded by **both** root pages. Toggles `.is-active` on `.navbar-burger` / `#navbar-main` for the mobile menu, and drives the navbar keypoint by writing `--kp-x` / `--kp-o` onto `.navbar-sections` (easing stays in CSS). Four non-obvious details, each commented at the code: the "current section" probe line **sweeps downward** as you near the bottom of the page rather than sitting under the navbar, because the last section is too close to the end for its heading to ever climb that high; a document-level click listener re-measures on a `setTimeout` (not rAF, which is suspended in background tabs) because expanding an abstract moves every section below it; the mobile menu closes itself after a jump (bound **before** the scroll-spy's early return, so it still works on a page with nothing to track); and when *no* link resolves to a section on this page — the résumé, whose rail points back at the homepage — it parks the dot under whichever link the markup already marked `.is-active` and re-parks it on `load` and `resize`, since the rail shifts when the webfont lands. Nav links are plain anchors, so navigation degrades without JS.

  **Cross-page keypoint continuity** is the one piece of nav.js that spans documents, and it is ordering-sensitive. Moving between the two root pages is two separate loads, so the dot would ordinarily just appear under the new page's label; instead each page writes the **label text** of the link the dot ended under to `sessionStorage`, and the next page's first `moveKeypoint()` places the dot there before moving it to its own — the glide is the existing CSS transition, handed a different starting point. Four things hold it up: the placement is wrapped in `.navbar-sections.is-instant` (which zeroes the dot's transitions) so arriving at the start point isn't itself animated; a **forced reflow** (`void rail.offsetWidth`) sits between the two writes, without which the browser coalesces them into one style change and nothing animates; the key is the label, **not an index**, so it still resolves if the two rails ever differ; and the whole keypoint block must stay **above** the `!targets.length` early return, because the résumé page calls `moveKeypoint()` from inside that branch and `var`s declared below it would still be `undefined`. Opacity is only forced during the instant placement when there *is* a journey — with no stored label the dot fades in where it belongs instead of flying in from the rail's left edge. Under `prefers-reduced-motion` the CSS transitions are already off, so the whole thing collapses to a plain placement with no JS check needed. Verify a change here by reading `getAnimations()[0].effect.getKeyframes()` on `.nav-keypoint` right after a navigation — an automated tab often isn't painting, so a sampled `getComputedStyle().transform` will sit frozen at the start value and look like a bug that isn't there.
- Inline JS in `index.html` — `display(id)` toggles a publication's abstract; an `IntersectionObserver` (`rootMargin: 200px`) plays/pauses `video.lazy-video`; a one-liner fills `#copyright-year`. StatCounter (project `12925377`) loads at the end of `<body>` — the same project also loads on `unimate/`, but not on `dimo/` or `resume.html`.

**Site nav**: the homepage and `publications.html` both run a two-link rail — About, Publications. **Resume is deliberately in neither**: the résumé page is reachable by URL (and keeps all three links on its own rail, where Resume carries `is-active` for the keypoint to park under). The keypoint's cross-page continuity is keyed by label, so the rail difference degrades gracefully: a stored label with no match on the next page simply fades the dot in at its destination. `#About` is not a section; it is the `id` on `.hero` itself (`<div class="container hero" id="About">`). The homepage's `#Publications`, `#Experience` and `#Service` exist as sections but are deliberately **not** in the nav — the rail's Publications is the *page* `/publications.html` (the full record), not the homepage's Recent Research section. Publications and Resume are *pages*, so `nav.js` skips them when tracking on the homepage and the keypoint never parks there; on `publications.html` and `resume.html` About is written as `/#About` (it leaves the page), and each page's own link carries `is-active` + `aria-current="page"` in the markup, which is what the keypoint reads. Adding a link means adding a section with a matching `id` — otherwise it is inert in the rail.

That leaves the homepage with exactly one tracked section, so its keypoint parks under About and stays: the scroll-spy still runs, it just has nothing to move between. The machinery in `nav.js` is kept as-is rather than trimmed to fit, because the rail is a section index by design and the previous two edits both changed which sections were on it.

**Section reveal** (both root pages; modelled on `ying-hui-he.github.io/cv.html`, whose sections carry `.fade-in` + a `.visible` class added on scroll):
- **Nothing above the first section animates.** `.hero` and the résumé masthead render with the page, and carry no rule at all. Both briefly had a staggered rise and it was the wrong thing to animate — that block is what the visitor came for and the only one certain to be on screen, so delaying it delays the one thing that should already be there, and there is no scroll position at which to reveal it. The reference does the same: its masthead has no `.fade-in`. The entrance begins at *Recent Research* and at *Education*.
- **Sections unfold when they reach the viewport**, via `revealSections()` in `nav.js` adding `.is-in`. A fixed load stagger spends its later steps on content below the fold, and a fast scroller arrives to find a section already half-finished. Sections in view at load are stepped 90ms apart starting at 0.
- **The timing is derived, not picked** — this is what keeps it coordinated. The site owns exactly one piece of travel, the nav keypoint (`transform 420ms cubic-bezier(0.34, 1.2, 0.64, 1), opacity 220ms`); everything else is a 120–250ms colour or hover change. The reveal is the only other thing that moves, so it runs on the keypoint's clock — 420ms travel, 220ms fade, same split — with that curve's overshoot removed (`y1 1.2 → 0.9`), because a dot may spring past its mark and return but a section springing past its resting position would shove the page. Travel is **10px, not the 16px** the reference uses and every template repeats: nothing else here moves more than a few px, and 10 settles where 16 slides. If you retime this, retime it against the keypoint or the two will visibly disagree.

Four things here are load-bearing, and three of them are about never showing a blank page:
- **The hidden state is gated behind `.js-anim`**, set by a one-line inline `<script>` in each page's `<head>`. It must stay in the head: it lands before any section is parsed (so there is no frame where sections show and are then hidden), and it means the hidden state exists *only* when JS runs. The reference's own `.fade-in { opacity: 0 }` is unconditional — with JS off that page is permanently blank. Don't copy that.
- **Sections already in the viewport are revealed from their own measured `getBoundingClientRect()`, not from the observer's first callback.** The obvious way to write this hands everything to the observer, which makes every pixel above the fold depend on it firing. Only what starts below the fold is observed, where nothing is on screen to be missing.
- `animation-fill-mode: **backwards**` on the top block puts the from-state only in the keyframe, so if the animation never runs the elements simply render visible.
- A **3s failsafe** reveals the below-fold sections if the observer never delivers, and no-`IntersectionObserver` / `prefers-reduced-motion` reveal everything up front. `@media print` in `styles.css` overrides the hidden state outright — a section nobody scrolled to is legitimately at `opacity: 0` when Cmd-P is pressed, and paper has no second chance.

Verify a change by cancelling the animations (`el.getAnimations().forEach(a => a.finish())`) and confirming `opacity: 1`, and by removing `.js-anim` and confirming nothing is hidden. Note an automated tab often isn't painting, so **`IntersectionObserver` never fires there** — below-fold sections will look stuck until the 3s failsafe; that is the harness, not the code.

**Publications pattern**: Publications live under `#Publications` (headed "Recent Research"; the `id` is still `Publications`), split into `.section-h3` subsections `#Vision` ("Vision & Graphics") and `#Robotics` ("Robotics & RL"). Each entry is a `.pub-row.row`: a video/image thumbnail in `.col-md-3` and details (`.pub-title` / `.pub-authors` / `.pub-venue` / `.pub-links`) in `.col-md-9`. Abstract text is hidden in a `<div id="*-abs" class="pub-abstract">` block, toggled by `onclick="display('*-abs')"`. All five live thumbnails carry `class="lazy-video"`, so the observer plays them only while on screen; the Robotics trio (`ttt-parkour`, `vr-robo`, `rrw`) additionally sets `preload="none"` so they don't fetch until then, while the two above the fold (`unimate`, `dimo`) keep `preload="metadata"` and `autoplay`. "Let Occ Flow" is isolated in a `<template>` (parsed but never rendered, and its video has no `lazy-video` class since it never displays); its `assets/let-occ-flow.mp4` stays in the repo.

**Homepage media**: Publication thumbnails live flat in `assets/`, each named after the work (e.g. `dimo.mp4`, `unimate.mp4`, `ttt-parkour.mp4`, `vr-robo.mp4`). Affiliation/company logos carry a `-logo` suffix (`meta-logo.png`); `princeton-logo.jpg` doubles as the favicon and the navbar brand mark. Poster PDFs sit alongside them. Every file in `assets/`, `dimo/assets/` and `unimate/assets/**` is currently referenced — there are no orphans, so an unreferenced file is a mistake, not spare inventory. (The paper PDF lives at `unimate/resources/unimate.pdf` and is linked from the résumé page's publications.)

## Indexing

Search-engine visibility is set **per page**, and the pieces interact — read this before touching `robots.txt`, `sitemap.xml`, or a `robots` meta tag.

| Page | `robots` | `canonical` | In sitemap |
|---|---|---|---|
| `/` | (none — indexable) | `linzhanmou.com/` | yes |
| `/publications.html` | `index, follow` | `linzhanmou.com/publications.html` | yes |
| `/dimo/` | `index, follow` | `linzhanmou.com/dimo/` | yes |
| `/unimate/` | `index, follow` | `linzhanmou.com/unimate/` | yes |
| `/unimate/interactive.html` | `noindex, follow` | none | no |
| `/resume.html` | `noindex, nofollow` | **none, on purpose** | no |

- **`/resume.html` is kept out of search results, but stays crawlable in `robots.txt`.** These two mechanisms conflict if combined: a `Disallow` stops the fetch, so the `noindex` is never read, and the URL can linger in the index as a bare link. Crawling must be allowed for the tag to work. `resume.pdf` is the one path `Disallow`ed outright, because a PDF cannot carry a meta tag and Pages cannot send `X-Robots-Tag`.
- **No `canonical` on `/resume.html`** — `canonical` asserts "index this URL", which contradicts `noindex`.
- The page is **unlinked from the other pages' rails again** (belt-and-braces, alongside `noindex`): only its own rail and the URL reach it. `noindex` still does the real work — it is read precisely because crawling is allowed. Don't remove it. The **only** link to `resume.pdf` is the "PDF" item in the résumé's own contact line, which changes nothing for search: that page is `nofollow` and the file is `Disallow`ed anyway. Don't link the PDF from an indexable page.
- `/resume/` no longer serves a page, so the old URL 404s. It was unlinked and noindexed, so nothing points at it.
- The `google-site-verification` meta lives in `index.html`.
- Keep `sitemap.xml` and the meta tags in agreement: a `noindex` page must not be listed.
- **Update a page's `<lastmod>` when you change that page.** It is a recrawl signal: a stale date says "settled, don't bother", which is exactly wrong after an edit, and a date bumped without a real edit trains Google to ignore the field. Take it from `git log` on the page's file. Two traps: XML comments **cannot contain a double hyphen** (so no git flags pasted into them — this silently broke the file once), and the date must be `YYYY-MM-DD` and not in the future. Validate with `xmllint --noout sitemap.xml` before pushing.

## Résumé page (`resume.html`)

Two artifacts from one source of truth, plus a shared design layer:

- **`resume.html`** — the HTML résumé, at the root beside `index.html`. Loads `custom-navbar.css` + `styles.css` + `nav.js` (all shared with the homepage) then `resume.css` on top. Sections: `#education`, `#internship`, `#experience`, `#publications`, `#awards`, and Professional Service — headings, not nav targets: the page is one document read top to bottom and carries the *site* nav, not an index of itself. The link to the built `resume.pdf` lives in the masthead contact line (new tab — it leaves the page for a file, and a PDF viewer has no way back), which is where it went when the page's own two-link navbar was replaced.
  - **`.resume-pdf` is a control, not a link** — a filled accent-tinted plate carrying a document mark and a verb ("Download PDF"), modelled on the CV page at `ying-hui-he.github.io/cv.html`. It sits *after* LinkedIn with a gap instead of a `·`: the rest of that line is names you follow, and this is the one item that hands you a file. Four things are load-bearing. The fill is a **9% `color-mix` wash of `--accent`, not `--accent-bg`** — that token is the page's tinted surface and is the obvious pick, but `#fdf6ee` on this page's `#faf9f5` is roughly 1.02:1 and the plate never appears; a flat hex is declared first as the fallback for anything without `color-mix`. It takes **`--radius-md`, not `--radius-sm`**, because the softness is most of what reads as pressable and 3px on a 30px plate is a hairline box again. Hover deepens the wash and draws the accent ring with **`box-shadow: inset`** rather than a border, so the plate gains an edge without gaining a pixel — a real border reflows the whole contact line by 2px on every hover. And the mark is **inline SVG**, never an icon font: this page deliberately drops Font Awesome and Academicons, and two paths cost no stylesheet. The ink stays `--text-primary`, so the accent still never colours a glyph. It is `display: none` in the print sheet — on paper you are already holding the PDF. An earlier pass made it a hairline box with a notched corner (a sheet of paper rather than a button); that was replaced, so don't reintroduce a cut corner alongside the fill.
- **`css/resume.css`** — the document layer, and no navbar layer: the two-sided `.resume-row` (role left, dates right), the masthead, section rules, and a **`@media print` sheet** so Cmd-P yields the résumé rather than a screenshot of a website (chrome hidden, background flattened, `break-inside: avoid` on entries). `.resume-page` is `max-width: 60rem` — wider than a prose measure because the two-sided rows need it; the header comment explains why 47rem broke them. Its type rules deliberately spend each face once: Fraunces for the name only, Source Serif for places/roles, Palatino for publication titles — so two similar-looking 18px lines are telling you something true.
- **`resources/resume/`** — `resume.tex` (pdflatex, `libertine` + `fontawesome`), the served `resume.pdf`, and `build.sh`, which compiles the PDF in place and then cleans every intermediate. **Run `./resources/resume/build.sh` after editing `resume.tex`** — `resume.pdf` is a build artifact and editing the `.tex` alone leaves the served PDF stale, including any URLs baked into its text layer. `resources/resume/.gitignore` ignores generated PDFs and latexmk intermediates as a safety net for interrupted builds; the already tracked `resume.pdf` remains the served artifact.

## `dimo/`

Self-contained, custom-designed project page for the DIMO paper — no Bootstrap, no shared assets, no `?v=` cache busting. All styling is in `dimo/css/style.css` (design tokens at `:root`); markup is in `dimo/index.html`; the only script is `dimo/js/nav.js`. Loads Academicons, Font Awesome 4, and the Inter / Newsreader / Space Grotesk / Space Mono fonts from CDNs. All media lives flat under `dimo/assets/` — `teaser.png`, `pipeline.png`, `interpolation.mp4`, `language.mp4`, `spinner.svg` (used as the two videos' `poster`), `favicon.svg`. There is no `dimo/img/` dir and no paper PDF in the repo: the arXiv, poster, and video buttons all point off-site, and `#demo` is a YouTube `<iframe>`.

- **Design system**: a dark "latent-space" hero over a light "paper" body. Tokens split the same way — `--space*` / `--on-space*` for the hero, `--paper*` / `--ink*` / `--line` for the body — plus a reserved blue→violet→pink `--spectrum` gradient used **only** on the title, the active nav node, the nav progress fill, and `favicon.svg`. Sections (`#demo`, `#applications`, `#abstract`, `#method`, `#poster`, `#cite`, in DOM order) alternate `.section` / `.section--alt` for a white / `--paper-2` tint (no borders). Each header is a mono `.kicker` + a `.section-title`.
- **Signature**: the hero figure is an inline SVG (`.field`) where one origin keypoint fans into five trajectories ending in CSS/SMIL-animated stick-figure skeletons (wave/walk/kick/jump/turn). Limbs rotate via `transform-box: view-box` with per-limb `transform-origin`; `prefers-reduced-motion` freezes them and hides the traveling `.kp` dots.
- **Figure captions** (`.caption`, the two Applications videos — the teaser/pipeline/poster images carry none): set as the paper's own figure captions are, a **bold `--ink` run-in naming the application followed by the mechanism in one `--mute` sentence**, taken from Fig. 6 / Fig. 7 and §4.3 of the arXiv paper. Space Mono 700 is already in the font request, so the run-in costs nothing. Three things were wrong before and are worth not reintroducing: the caption sat 18px under its own video and **0px** above the next one, so it read as a label on the wrong figure — `.media + .media` never matched, because a caption always sits between them, which is why `.caption + .media` now carries the 40px; the spacing scale is 14 within a figure / 40 between figures / 52 between sections, each boundary louder than the one inside it; and at `0.82rem` the caption was 13.1px against the `.kicker` eyebrow's 12.5px, so a sentence was set at the size of a tag while the prose ran at 18.9px. It spans the container, so it already aligns with the figure's left and right edges — no rule needed.
- **Side nav** (`.sidenav`): a fixed vertical "trajectory" rail in the left gutter, right-anchored so labels never crowd the content; **hidden below 1480px** (`@media (max-width: 1480px)`). `nav.js` uses one `IntersectionObserver` to reveal it once the hero leaves the viewport and another (`rootMargin: -45%/-50%`) to set the `.is-active` node and drive the `--nav-progress` spectrum fill. Links are plain anchors, so it degrades without JS.

Four things are load-bearing:

That is what makes the plate restart *as a plate*: at 9s every figure, chip and tick resets together. (Three delayed 3s clocks were the obvious way to stagger the turns and cost exactly that — a figure was still standing there from the last round while the first one started over.) The rig is a bird, not the humanoid the other plates use, and the three motions are *different* and named on their chips so the reader can check the drawing against the word — **1 · takes off** (wings beat down, body rises, legs fold), **2 · strikes forward** (coil, a dead beat, then head/wings/legs all fire on one), **3 · lands** (wings brake open, legs unfold, body settles). They are authored as explicit per-bone stop tables in `schematics.css`, where **each motion's last pose is the next one's first** — edit a motion's opening stop and you must edit the previous one's closing stop with it, or the chain comes apart at that seam; `animation-fill-mode: both` is what makes the seam work, since a figure holds its opening pose through the whole stretch of master before its window opens, appearing already in the pose the figure above it is holding. Easing is **per keyframe** here, not per track: a group `ease-in-out` decelerates to a dead stop at every waypoint, which turned the take-off into three visible lurches. The progress bar fills a third per turn, by animating dash **length** (`stroke-dasharray: 0 1 → 1 1`) rather than `dashoffset`: on a `pathLength="1"` stroke an offset of 1 doesn't hide the dash, it slides the pattern's next repeat onto the path's final point, which showed up as a stray dot parked at the bottom of the plate. A limb's own joint is drawn by its **parent**, never inside the rotating group — see the pivot rule below.
  - **The trap that cost a rebuild**: `transform-box: view-box` resolves `transform-origin` against the **root viewBox**, not the rig's local space — inside a translated, scaled group every pivot lands off the body and the limbs fan out from nowhere. The bones are therefore drawn so each joint *is* a corner of that bone's own box, and the pivots are `transform-box: fill-box` + `100% 0%` (left side) / `0% 0%` (right). Where the terminal sits took three tries, and the middle answer is the one to keep. At the rig's **centre** it was always on the creature but the leader had to cross half a body to reach it — length is what makes these read as tethers rather than labels. Slot scoring charges for distance too (`LEADER_COST`, in chip-areas per 100px) — without that term the solver happily buys a clear patch of floor with a leader half the frame long. **How much it charges depends on how crowded the stage is.** `spread` runs 0 at four chips to 1 at nine: on a roomy stage every chip sits tight against its own rig, and as the count climbs the distance charge halves, the side/corner penalties fall away, and a candidate standing clear of every rig on the stage — out in the left or right margin — earns `MARGIN_BONUS` back. The margins are there to relieve a jam, not to be occupied: without the cap the chips ran to the canvas edges and the picture read far wider than the group actually is. The text is **content, so it lives in `unimate/resources/prompts.json`** (beside `resources/glbs/`, not inside it), keyed by glb filename — edit prompts there; `examples.js` only carries a per-file `prompt` when one stage needs to override the shared line (`''` suppresses a label). House style for the copy is **the paper's own captioning format** (Appendix A.5, in `resources/unimate.pdf`): `'An [object type] [action].'` — one sentence, under 12 words, one dominant action, a direction only where clearly observed, no adverbs, and the object named concretely ("A robot", "An eagle") rather than as "An object". Never invent a prompt from a filename — there are two ways to find out what a clip actually does, and `resources/prompts.json` records which one each line came from (`_from_caption` = the original prompt; everything else = written from the motion). **First**, 23 of the rigs are captioned in the videos themselves: `assets/diverse-1..3.mp4` and `prompt-eagle/-shark/-bighero.mp4` caption the same rigs the viewer loads, so pull a frame with ffmpeg — the `posters/*.jpg` are t=0, before the caption types in, so they are blank. **Second**, for the rest, look at the animation: Blender is installed (`/Applications/Blender.app/Contents/MacOS/Blender -b -P script.py`), and a headless pass that imports each glb, samples the armature (net travel, rise, yaw, per-limb activity — all in body-height units) and renders a 6-frame filmstrip settles it in one run. That pass is what corrected the guesses: `ironman-walk` and `quadruped` walk **in place** rather than forward, `whale` never travels (only its tail sweeps), `whale` never travels (only its tail sweeps), and `dragon-fire` hovers rather than breathing fire. Three gotchas if you redo it — the mechs are near-black, so render `color_type = 'SINGLE'` or they are unreadable silhouettes; the clip name is `Reconstructed_Action` for every rig, so the file itself tells you nothing; and a render shows you the motion but **not the dataset's word for it**, which is the failure mode that actually bit. The prompt set reuses a small vocabulary, so reach for a verb already attested in `_from_caption` before coining a precise one: the chicken's head dip and the stego's rear-up read as "pecks at the ground" and "rears and swings its tail", but both are the same "attacks forward" that captions the piranha plant, and the monster's creep is "walks in place". Chips are sized (`max-width: 250px`) to keep a prompt in that format on one line — the forty read as a series only while none of them wrap. Chip placement is a small annotation-layout solver, and every piece of it is load-bearing. **Four slots**: each frame every rig is projected to a screen box (`screenBox`, from the local box `groundAndNormalize` stashes on the pivot) and the chip's four candidate positions — above, below, left, right — are scored by how much *model* each would cover, plus a preference (above is free, below costs a little, a side slot more, and a side slot pointing back INTO the group most). The cheapest wins, so a two-row diorama sends the front row's chips onto the empty floor and the back row's into the empty sky, while a rig at the end of the group puts its chip out into the margin beside it. The toolbar is scored as an obstacle too (`GUI_COST`) — without that, a chip whose rig sits under the panel picks "above", collides, and gets shoved clear across the frame. The choice is sticky (`SLOT_HYSTERESIS`) so an orbit through a near-tie doesn't make chips hop. **Escape**: collisions are resolved near→far, along the chip's own axis, with each step taken only if it can *actually* clear the blocker — a move clamped short of clearing leaves the overlap and spins the loop. The chain is: out along the axis within `MAX_LIFT` → slide across → overrun the cap → cross to the far side → and a last-resort stepped search from the rest position. **Baseline snap**: chips in the same slot within `BASELINE_SNAP` of each other align on one line, so rigs of different heights don't give every chip its own level. **Damping**: positions ease toward their target (`SETTLE_TAU`), so a slot flip or a resolved collision glides instead of teleporting mid-orbit; `SETTLE_SNAP` takes big jumps instantly, and `prefers-reduced-motion` skips the easing. **Chips recede with depth** — opacity and scale fall off with distance, measured as a *fraction* of the nearest chip's distance (`DEPTH_SPAN`), which lets a side-by-side row stay uniform while a second row drops behind. Two stages carry a deliberately generous `pad` (Creatures 1.35, Armored Robot 1.3) purely to give the label bands somewhere to live; tighten either and the chips are squeezed against the canvas edge. Note the leader's offsets and length are divided by the chip's scale, since it is a child of the chip and would otherwise stop short of its pin. Four things the placement does that are easy to undo by accident: chips are clamped inside the canvas and out of the toolbar's column (they are opaque and would eat each other's text), a near→far pass lifts colliding chips apart (capped at `MAX_LIFT`, which the 9-model Creatures stage actually reaches), box sizes are **cached** (`measureLabels`) rather than read per frame so anything changing a chip's size must re-measure (resize, webfont load, and toolbar collapse already do), and the anchor rides the **75th-percentile** per-frame mesh top, not the max — the max is set by one extreme frame (a backflip's peak) and pinning to it parks the chip a body-length above the rig for the whole rest of the clip.
