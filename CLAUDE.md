# CLAUDE.md

Guidance for Claude Code working in this repo. It records the **non-obvious** — constraints, traps, and decisions that would otherwise be re-litigated. Structure, file lists and rationale that are already legible in the source or its comments are deliberately not repeated here; read the files.

## Overview

Personal academic homepage for Linzhan Mou, served by GitHub Pages at `linzhanmou.com`. **No build system, no package manager, no server-side code** — the one build step is the LaTeX résumé. Preview with `python3 -m http.server 8000`. Deploy by pushing to `main`; a feature branch does not deploy. All media is committed directly (no LFS). Pages cannot set response headers, so `robots.txt` and `<meta>` are the only levers.

**Domain**: root `CNAME` holds `linzhanmou.com`; `www`, both `http` variants and `linzhanm.github.io` each 301 to it. Don't delete `CNAME`. **Every absolute self-link must use `linzhanmou.com`** — any other host costs a redundant DNS+TLS handshake (~2× load time).

## Layout and conventions

Six pages in two groups, plus the two framed labs in `resources/overview/`. `index.html`, `publications.html`, `resume.html` sit at the root and **share** `css/styles.css` + `css/custom-navbar.css` + `js/nav.js` **and the navbar markup** (brand, appearance switch, burger, menu — plus the identical inline head scripts for `.js-anim` and `data-theme`), which differs by exactly two deliberate things: the résumé's rail adds a third link for itself, and About is `#About` on the homepage but `/#About` off it. Any other difference between their navbars is a bug, not a variant. `dimo/` and `unimate/` are fully self-contained and share nothing with them or each other. The homepage's two live thumbnails are a third tree, `resources/overview/` (section below): labs kept for that frame alone, so `dimo/` and `unimate/` never change for the homepage's sake.

**Media convention, all three trees**: `assets/` is split by type — `videos/`, `images/`, `logos/`, `posters/` — and only the types a page has are present. New media goes in the folder for its type; never loose in an `assets/` root.

**Nothing here is spare inventory**, and it was audited on 2026-09-07: every file under `assets/**`, every `.glb`, every CSS class defined in a stylesheet, and every JS declaration is reachable from a page. Root `favicon.ico` is the one file nothing links to — browsers request it at the root by convention. So an unreferenced file or an unused rule is a mistake or a leftover, not a reserve; delete it rather than working around it.

**Directory names are public URLs.** `/dimo/` and `/unimate/` are in `sitemap.xml`, carry `canonical` tags, and are linked off-site; the three root pages must stay at the root for Pages to serve them. Reorganize freely *inside* those directories — moving the directories breaks live links.

**Cache busting**: local `<link>`/`<script>` carry `?v=N`, because Pages caches aggressively.
- `styles.css`, `custom-navbar.css`, `nav.js` are referenced from **all three root pages — bump N in all three**, and keep the numbers equal so one URL means one cache entry. They drifted once and left the résumé on a stale stylesheet.
- `resume.css` and `publications.css` are single-page and carry their own counters. `dimo/` uses no `?v=` at all. Both labs under `resources/overview/` version their whole module graphs like `unimate/` (chains in their sections below).
- `unimate/` versions **everything local, including every ES-module import** (entry → `viewer.js` → `examples.js` → `showcase.js`). Bump at each import site and walk the bump up to the HTML — a stale module is a broken viewer, not a stale style. See `unimate/README.md`.
- A **comment-only edit takes no bump**. The counter exists so a visitor's browser picks up changed *behaviour*; spending one on a reflowed comment invalidates the cache for every visitor and buys nothing.

**Styling**: `index.html` and `resume.html` carry **no inline `style=` and no `<br>` spacers** — both are at zero of each; keep it that way. Sections are `<section class="container page-section">`; the Bootstrap `.container` is required because `.row`'s −15px margins need its padding to cancel them.

Change one and change the other.

**Design tokens** (`:root` in `styles.css`) are a system — stay on them rather than hard-coding:
- **Radius** is three fixed-px steps on purpose; percentages resolve against the box and turn non-square elements into shape-shifting ellipses. A circle (the nav keypoint) is a shape, not a step, and stays `50%`.
- **Elevation** is two layers each (tight contact + diffuse ambient), so media reads as set *onto* paper.
- **Accent `#E77500` is for geometry only** — rules, borders, the keypoint, link underlines. Never the colour of running text: orange dark enough to pass AA on ivory is orange gone brown.

**Three CSS rules to keep in mind**:
- `styles.css` loads **after** `custom-navbar.css`, so a `.navbar` rule placed there silently wins. Keep navbar chrome in `custom-navbar.css`; `styles.css` currently has none.
- `resume.css` touches the navbar only to hide it in `@media print`. Don't reintroduce a per-page navbar layer — the pages share the markup.
- Bootstrap defines `.navbar` as flex with `0.5rem 1rem` padding; `custom-navbar.css` zeroes it and gives `.navbar-inner` `width: 100%`. Don't remove either without re-checking layout.

### Appearance (light and dark)

Since 2026-09-12. One attribute, `html[data-theme]`, drives everything; `prefers-color-scheme` is read only as the fallback while no choice is stored.

- **Where it is decided.** An inline script in each root page's `<head>` — identical on all three, beside the `.js-anim` gate, and it must stay in the head so the first paint is the right palette — stamps the stored choice (`localStorage` `theme`), else the system appearance. With JS off the page is light.
- **The switch.** `.theme-switch` on the navbar, between `.navbar-brand` and `.navbar-burger` (the burger no longer sits inside the brand): after the rail on desktop, beside the burger on a phone — one element, reordered by CSS. `nav.js` flips the attribute, stores the choice, and follows the system only until one is made; there is no third "system" state (as on darioamodei.com, the owner's reference). It also rewrites the `theme-color` meta so Safari's toolbar tints. The drawing is that site's pill scaled to the rail: 32 × 18, a 12px ink knob, the track in the plate tone, a ring in the labels' grey that goes to ink on hover — never the accent. Three drawings were taken out the same day at the owner's request: an orange-knobbed pill, two page swatches with the keypoint under the one in use, and the reference pill copied exactly with its inverted dark fill. Bootstrap's `button:focus` ring is suppressed for mouse focus on it and the burger; keyboard focus keeps the accent ring.
- **The tokens.** `styles.css` re-values only the surface, text and shadow tokens under `@media screen { :root[data-theme="dark"] }` (`screen` so paper prints light). Nothing else changes, so a hard-coded colour is what breaks dark mode: the navbar's translucent fill is `color-mix` off `--ivory-light`, and `publications.css`'s `--spine` carries its own dark value. Surfaces crossfade 200 ms on a switch — the knob's own clock — and not at load, since the attribute lands before first paint. **Dark is the UniMate lab's dark** (`unimate/interactive#welcome`, the owner's reference): the plate (`--ivory-medium`) is its `#151817` sky and the page that family a step lighter (`#1e2120`) — the inverse of light, where the plate is a step darker than the page. A warm ink dark was tried and replaced.
- **The framed labs.** Each thumbnail's head reads the parent's attribute (`pageTheme()`, same-origin; the system query is the fallback) and its `viewer.js` watches it with a `MutationObserver`, so the stages turn with the page. Framed and dark, both take the plate as their sky and the UniMate lab's checker as their floor (`['#35312c', '#222321']` at 0.88, one square per paper cell, a `checker` branch in each floor painter — `paper.checker` in UniMate's copy, `grid.checker` in DIMO's); light keeps the graph paper. The values are literal in each lab's `viewer.js` and `interactive.css` (what shows before the scene paints), so change `--ivory-medium` and all four together. An off-white dark floor was tried and replaced.
- **The full labs share the key.** `unimate/interactive.html` and the DIMO lab open in the stored `theme` — dark, their own default, when none is stored, not the system's — and their Theme buttons write it, so the site and the labs are one setting (the DIMO lab's former `dimo-lab-theme` key is gone).
- **Not done.** The phone recordings below `md` are rendered over ivory and stay so in dark.

### Nav and the keypoint (`js/nav.js`)

The rail is a **section index**. Adding a link means adding a section with a matching `id`, or it is inert. `#About` is the `id` on `.hero` itself. Publications and Resume are *pages*, so nav.js skips them when tracking; each page marks its own link `is-active` + `aria-current` in markup, which is what the keypoint reads. The homepage and `publications.html` run About + Publications; **Resume is on neither** — only the résumé's own rail carries it (belt-and-braces alongside its `noindex`).

**Cross-page keypoint continuity** is the one piece spanning documents, and it is ordering-sensitive. Each page stores the **label text** (not an index) of the link the dot ended under; the next page places the dot there before moving it to its own, so the glide is just the existing CSS transition given a different start. Four things hold it up: the placement is wrapped in `.is-instant` (zeroing transitions) so arriving isn't itself animated; a **forced reflow** (`void rail.offsetWidth`) between the two writes is required or the browser coalesces them and nothing animates; the key is the label so it survives differing rails; and the whole block must stay **above** the `!targets.length` early return, since the résumé calls `moveKeypoint()` from inside that branch.

### Section reveal

Sections unfold as they reach the viewport; **nothing above the first section animates** — the hero and résumé masthead are what the visitor came for and the only blocks certain to be on screen. Timing is **derived, not picked**: it runs on the keypoint's clock (420ms travel / 220ms fade) with the overshoot removed, and 10px of travel rather than the 16px every template repeats. Retime it against the keypoint or the two visibly disagree.

Four load-bearing details, three of them about never showing a blank page:
- The hidden state is gated behind **`.js-anim`**, set by an inline script in each `<head>`. It must stay in the head, and it means the hidden state exists *only* when JS runs — an unconditional `opacity: 0` would leave a JS-off page permanently blank.
- Sections already in the viewport are revealed from their **own measured `getBoundingClientRect()`**, not the observer's first callback, so nothing above the fold depends on the observer firing.
- `animation-fill-mode: backwards` keeps the from-state in the keyframe only.
- A **3s failsafe**, plus no-`IntersectionObserver` / reduced-motion paths, reveal everything; `@media print` overrides the hidden state outright, since paper has no second chance.

Verify by finishing all animations and confirming `opacity: 1`, and by removing `.js-anim` and confirming nothing is hidden.

## Indexing

| Page | `robots` | `canonical` | In sitemap |
|---|---|---|---|
| `/`, `/publications.html`, `/dimo/`, `/unimate/` | indexable | yes | yes |
| `/unimate/interactive.html`, `/resources/overview/*/interactive.html` | `noindex, follow` | none | no |
| `/resume.html` | `noindex, nofollow` | **none, on purpose** | no |

- `/resume.html` is kept out of results but stays **crawlable** in `robots.txt`. The two mechanisms conflict: a `Disallow` stops the fetch, so the `noindex` is never read and the URL can linger as a bare link. `resume.pdf` is the one path `Disallow`ed outright, because a PDF can't carry a meta tag.
- No `canonical` on `/resume.html` — it asserts "index this URL", contradicting `noindex`. Don't link `resume.pdf` from an indexable page.
- Keep `sitemap.xml` and the meta tags in agreement, and **update a page's `<lastmod>` when you change it** (take the date from `git log`) — a stale date says "settled", a date bumped without an edit trains Google to ignore the field. Two traps: XML comments **cannot contain a double hyphen**, and the date must be `YYYY-MM-DD`, not future. Validate with `xmllint --noout sitemap.xml`.

### `dimo/` — the DIMO Motion Lab

**The homepage's DIMO thumbnail** (`?embed`); without it, a full lab that only the homepage's phone cover link opens. Nothing on `dimo/index.html` links to it — a hero button and a Demo-section line were added and taken out on 2026-09-10 at the owner's request. Its favicon stays because the phone cover link opens the lab as a top-level page.

- **One scene per object, several bodies at once**, each with its own code on a 2-D latent sheet — the paper's claim. A combined stage of all objects was built and rejected; don't mix categories. The decoder is an RBF blend of basis motions; the panel says it illustrates the mechanism rather than running the trained model — keep that sentence.
- **The UR5e is the owner's skinned GLB** (`resources/glbs/ur5e.glb`; raw source in gitignored `dimo/resources/glbs-raw/`). The two shipped models (`ur5e.glb`, and `microduck-angry_head_snaps.glb` as the duck's) were made by `ship-glbs.mjs`, which put each raw GLB through UniMate's rig rules and compression, keeping the clips' 90 generated frames, densifying two-key samplers, and with **palette and join off**: the palette default baked the duck's colours into a texture `rigs.js` never reads (it recasts each part from its base colour), and join merges meshes across bones.
- **The robot duck opens the lab** (nine of the Microduck's own clips, `dimo/resources/glbs-raw/microduck_<motion>.glb`; the homepage thumbnail opens on it too, `#microduck`). **The current nine are the `source.file` fields in `js/microduck-motions.js`**: on 2026-09-11 electric slide and shy turn away replaced defiant beak up and peck twice, after the stashed generator's clip list was written, so a recovered tool needs its list updated before it runs. **Which clip stands where is `MICRODUCK_ORDER`** in `examples.js`, not clip order: play dead (falls back) and electric slide (slides right, so a rank's right end) in the front rank, back away at the back — chosen on 2026-09-11 over eleven layouts by clearance and occlusion measured across the loop (nearest pair 17.9 cm, was 10.2; no duck over a third hidden, was 46%) and by eye. A higher camera (0.48) halved the occlusion but shrank every duck in the thumbnail, and 4-3-2 / 2-3-4 pyramids either shrank them or left the frame's sides empty. Fourteen servos turn about their own z; its trunk floats (sits, lies down, backs away), so `model.joints` marks it `free: true` and it reads six controls, translation and XYZ Euler angles after rest. It stands ~0.29 tall, so it sets its own `spacing`, `depth` and `ringRadius`; the ring's default is sized for the UR5e. Every part is rigidly bound to one bone; `model.joints` in `examples.js` names the six joint bones and their bone-local axes; a primitive gripper hangs off `wrist_3_link`. Earlier builds converted the ROS meshes from URDF/Collada and carried a converter bug that stitched slivers across the arm; that path was deleted — don't revive it.
- **UR5e motions are the project's nine clips**, never downloaded or hand-authored: `dimo/resources/glbs-raw/ur5e_<motion>.glb` (dispense, inspect orbit, machine tend, palletize, peg insert, polish, pour, spray paint, weld weave) are the lab's own skinned UR5e with one 2.97 s animation each, and `extract-clips.mjs` read them into joint angles in `js/ur5e-motions.js` (and the duck's into `js/microduck-motions.js`) rather than shipping nine copies of a 15 MB model — generated data, so **never hand-edit those files**; recover the tool to regenerate them. It refused a clip that turns a bone off its lab axis, added π/2 to the pan (the clips face their viewer at −π/2), put wrapping joints on one branch because the decoder blends linearly, and looped each clip by cutting straight back to its first frame. An ease back to the start was added once and removed at the owner's request: it read as motion the model never made. A pipeline that pulled LeRobot demonstrations from Hugging Face was replaced by these clips on 2026-09-10 at the owner's request; don't revive it. `LATENT_SIGMA` (0.1) is sized to the anchor spacing so a body at its anchor plays ≥ 0.97 its own motion; at 0.17 every body was a third its neighbours and the nine averaged together. The lab's fingers hang past the flange the clips were authored to, so three clips reached below the floor (polish −7.6 cm, peg insert −5.1, dispense −1.7, measured 2026-09-13); `UR5E_RAISE` in `examples.js` lifts each at the shoulder (0.3 / 0.2 / 0.15 rad) with wrist 1 turned back the same, so the tool keeps its orientation and the fingers stay ≥ 2 cm clear — a catalog adjustment, not an edit of the generated clip data (owner's request, 2026-09-13: the second rank's right arm was sinking its gripper). `assets/videos/dimo-lab.mp4` predates it.
- **Framing is fitted, not tuned**: `frameCamera` takes every key point over each body's whole loop (plus scenery corners, and in the lab each name tag's chip, its height only below 720px so a phone's chips don't shrink the arms) and, for the object's `camera` (elevation, azimuth, optional `fov`), solves the closest distance at which all of them clear pixel insets from `interactive.js` (lab: head and dock; thumbnail: a hair), so nothing is cropped at that view. It is a closed form, not a search: with the direction fixed, each point's nearest allowed distance is linear in its view coordinates. The fog range is refitted with it, so no body is fogged. Don't reintroduce a hand-set distance or zoom factor; change `ranks`/`stagger`/`spacing`/`depth` or the view instead. ## `unimate/`

Two pages over one viewer engine: the project page and `interactive.html` (a full-screen "Motion Lab", dark chrome, `noindex`, not in the sitemap). The lab opens in the root pages' stored appearance (`localStorage` `theme`, read in its head; dark when none) and its Theme button writes that key back — one setting with the homepage's navbar switch, since 2026-09-12.

**Four stylesheets, three different organizing principles**, so a rule's home is decided by which: `style.css` is the page sheet, in ten numbered sections (§1 tokens … §10 footer); `schematics.css` is the Applications figure system, in four of its own (layout / rig / motion / responsive); `interactive.css` is the lab, including the lab's own breakpoints (900px, 560px); and `responsive.css` loads **last** and is organized by breakpoint, widest first (1000 / 720 / 600 / reduced motion) rather than by section. A component may keep its own breakpoint next to itself — the TOC and the schematics both do — so `responsive.css` is not the only place a media query may live.

**Two things in this tree are numbered with a `§`**, so a comment naming one must say which: `style.css §7` is a section of that stylesheet, `Experiments §1` is one of the page's four numbered Experiments subsections. Unqualified `§N` was ambiguous and is being retired — write the file or the word.

**One measure**: `.main-content` is 960px and *nothing* is wider — `--column` is that measure as a value. Widening a figure past it has been tried twice and reverted both times; a figure too big for the column gets **cropped and stepped**, not a breakout. Two gotchas: `--column` is off by a classic scrollbar's width (`100vw` counts it, layout doesn't), so anything exact takes a **percentage** instead; and `body` hard-codes its own background rather than using the tokens, so the page background is *not* `--ivory` — check which you mean before "fixing" one to match the other.

**Figure edges**: gallery clips carry a **1.5px `--slate-light` frame**; the teaser carries none. This is load-bearing, not decoration — the renders are white to the pixel at all four edges against a near-white page (~1.03:1), so only the drop shadow separates them, and it is offset 4px *down*: the bottom reads and the top dissolves. A `1px --rule` hairline (too faint) and `1.5px #000` (reads as a fence under the ink section plate) were both tried and rejected; an inset `box-shadow` ring does not paint over `<video>` at all.

**Experiments** run as four numbered subsections, all styled identically — §1 is the breadth gallery, §2–4 are controlled studies that are **two-up** (half the column each), so a strip always rests on two whole clips rather than showing half of a third. §1 is **one sheet per view**: each clip (`assets/videos/diverse-skeletons-N.mp4`) is a 2×4 sheet of prompt + result panels with the prompts baked in, sized to the full column because that text reads at 960px and not much below, stepped a whole sheet at a time with the arrows (gallery.js pages by what fits, here one) and snapped. Run `cropdetect` on a new export — one batch arrived letterboxed. gallery.js finds a row's scroller with `inner.closest(...)`, never `section.querySelector`. §1 was twice given a treatment marking it as a lead-in and both read as broken; keep the four uniform. **Below 720px the strips are not strips**: all four stack into a column (one clip per row at the column's width, read top to bottom) and every gallery's arrows are hidden, since 2026-09-09 — a sideways step is a second scroll axis under the thumb. §1's sheets stack too, whole and uncropped, so their baked-in prompts are small on a phone; that is the trade taken, over an oversized sheet panned column by column (200%/400%), which read as a cropped video. gallery.js needed no change for this: a column never overflows, so `advance()` bails on its own, and the buttons stay in the DOM because the script requires them.

**Dataset** (`#dataset`) comes **after** Applications, though the paper puts it at Sec. 4 — the visitor meets the model first and the corpus as supporting material. It is one real `<table>` set as a paper's algorithm float (caption above, rules top and bottom, numbered mono lines, no frame), because the content is genuinely tabular *words* that must stay selectable. Don't put numbers here that aren't in the paper. **Poster** (`#poster`) follows it and closes the content: `resources/unimate-poster.png` (3876×2582, ~4.5 MB) is served as the figure and is what every poster link opens, on this page and the root pages alike; the PDF is offered only from the caption. It lives in `resources/` beside the paper because it is a document, not page media. Keep it at roughly this size — an earlier 11880×7920 export was 19 MB, and a committed file that large costs the repo forever. **Application schematics** (`schematics.css` + inline SVG): each clip runs beside a portrait plate — the clip is the evidence, the drawing is the claim. **One convention across all three: ink is what you hand the model, accent is what it returns**, and accent here is *not* the page terracotta (`.app-row` re-points `--accent` at a slate blue, so the plates read as instruments). Each plate runs **one master clock** with every track an explicit window inside it — a track with a period of its own is what makes a plate come apart at the loop. On the expansion plate colour is a **state**, not a class (a figure is accent only while its motion is generating), which works only because its bones inherit the group `stroke`. Easing is **per keyframe**, not per track. The clips were rendered with their own titles baked in; a white patch covers them, and its geometry is **measured, not eyeballed** — re-measure before resizing, delete it if the videos are ever re-rendered without titles.

**The rig-drawing trap that cost a rebuild**: `transform-box: view-box` resolves `transform-origin` against the **root viewBox**, not the rig's local space, so inside a translated/scaled group every pivot lands off the body. Bones are therefore drawn so each joint *is* a corner of that bone's own box, with `transform-box: fill-box` pivots. Keep that true when editing a pose.

### Viewer engine

`examples.js` is the **data-only catalog, shared by both pages**; the two entry modules differ only in viewer config, and per-page framing goes in `stage-tuning.js` (keyed by stage label), **never a forked catalog**. `viewer-presets.js` holds `HIDDEN_CATEGORIES`. Hiding is **by label and filters the catalog before anything else reads it**, so a hidden stage costs nothing — but that is the trap: **hiding whatever stands first also changes what both pages open on**, and the lab's `#stage-name` first paint has to move with it. The Categories count is written from the data — don't maintain it by hand. Read the option vocabulary in the `examples.js` header before adding a stage; layout tuning belongs there, not in the engine. **A stage's `look`** (`viewer.js` `LOOKS`, since 2026-09-12) is how its rigs are lit and finished: `default` is the lab's own, and `dimo` — Tabletop's, at the owner's request, its duck, arm and lamp being that lab's kind of object — is the DIMO Motion Lab's studio brought over: a PMREM of three's `RoomEnvironment`, ACES at 0.88, its hemisphere / key / pink rim / blue fill at the values its homepage thumbnail settled on, and every material re-cast to its clearcoat shell or anodised metal by the file's own metalness (maps kept). `applyLook` runs on stage load and theme change and recompiles every material when tone mapping flips; the checker floor is `toneMapped: false` so it holds its colour under either. `lighting` multiplies the look's base intensities. **Rigs are sized by the tallest frame of their own clip**, so two clips of one character come out different sizes whenever one raises an arm (the G1 waving stood 14% short of the G1 picking up). A stage whose files are **one character** (every file shares the stem before the dash, detected by `oneCharacter()`; `sameRig` in the catalog overrides) gets `equalizeRigs()`: sizes matched by each rig's **bind-pose mesh** (`restSize`), the plainest-posed clip as reference — never a hand-set per-file `scale` to chase it (that was tried and overshot), and never bone length (EVE's three exports have identical bones under meshes of three sizes). Mixed stages keep the height rule; their rest sizes are not comparable. Every `.glb` is referenced — don't delete them.

**The rigs in `resources/glbs/` are compressed** (meshopt geometry + 512px WebP, 736 MB → 59 MB), so `viewer.js` registers `MeshoptDecoder` on its `GLTFLoader` — **drop that and every rig fails to parse**. WebP and quantization are native to three.js; meshopt is not. Uncompressed sources sit in the gitignored `resources/glbs-raw/` (the repo is the deployed artifact, and Pages caps a site at 1 GB). That folder is now the **only** copy: history was purged on 2026-08-06 (the old `b4ac4c8` recovery path is gone) because 2.3 GB of unreachable blobs had grown the repo to 1.63 GB and were stalling the Pages build past its 15-minute timeout. Keep history lean — a large file committed and then deleted still costs forever. A new rig must be run through the pipeline in `unimate/README.md` before it is committed. **Generator output is not in shipping form**: it arrives named `Reconstructed_Action`, with its unmoving channels as 2-key STEP tracks, and often with a fresh raw filename outside the `<category>-<action>` convention — rename, densify to 60 LINEAR keys and re-file *before* compressing, then verify the shipped file against the population (58 rigs today: one animation, 60 keys, every joint on three paths, no unreferenced sampler). The 2026-09-07 Tabletop rigs needed every one of those steps. Mesh-per-part exports (70 skins on one armature) and zero-offset joint roots both already exist in the set and are not faults.

**Prompts are content**, so they live in `unimate/resources/prompts.json`, keyed by glb filename; `examples.js` carries a `prompt` only to override (`''` suppresses). House style is the paper's own captioning format (Appendix A.5): `'An [object type] [action].'` — one sentence, under 12 words, one dominant action, no adverbs, the object named concretely. **Never invent a prompt from a filename.** Two ways to find out what a clip does, and `prompts.json` records which was used (`_from_caption` = the original): 22 rigs were captioned in the earlier `diverse-1..3` contact sheets (out of the repo since 2026-09-08; git history has them) and the `diverse-prompts-*` clips, plus 16 in today's `diverse-skeletons-1..2.mp4` (pull a frame with ffmpeg — the posters are t=0 and blank); for the rest, render the motion headlessly in Blender. That pass corrected real guesses (`ironman-walk` and the quadrupeds walk **in place**, `whale-sweep` never travels, `dragon_fire-hover` hovers). A render shows the motion but **not the dataset's word for it**, which is the failure mode that actually bit — reach for a verb already attested in `_from_caption` before coining a precise one.

**The label solver** places each chip in one of eight slots — the four sides plus four corner diagonals — scored by how much *model* it would cover (the toolbar counts as an obstacle, or a chip under it picks "above" and gets shoved across the frame), then resolves collisions near→far along the chip's own axis, snaps near-equal chips to a shared baseline, eases toward the target, and recedes with depth measured as a **fraction** of the nearest chip's distance. The leader is load-bearing, not decoration: chips dodge each other, so without it a lifted chip reads as belonging to whatever it ended up over. Both ends are **static** under a still camera — a version tracking the live pose was tried and removed, since a marker twitching with the animation reads as noise (and a 2026-09-08 version that followed walking rigs along a sampled track was removed the next day: the project page's viewer is not to change for the lab's sake). Box sizes are **cached**, so anything changing a chip's size must re-measure. Two boxes, for two different questions: `localBox` is the **typical** envelope (per-axis 15th/85th percentiles over the sampled frames, so one wing at the top of its beat doesn't hold every chip a wingspan out) and decides how close a chip may sit; `localBoxFull` is the full envelope and is what must never be covered. The anchor itself is neither — it sits at the **centre** of the mesh's envelope, because every edge point is usually empty air and a mark hanging in space says nothing about which rig it means.

**The lab has two prompt modes.** Hover mode shows one prompt at a time, as a tooltip beside the cursor (`hoverPrompts`). Three pieces must agree: a `pointermove` listener raycasts and stores the rig index; `applyLabels()` hides every other chip; and `updateLabels()` takes an **early-return branch** that places the survivor beside the cursor and hides the pins. That branch returns before the anchored solver runs, so **none of the machinery above executes in hover mode** — don't add hover behaviour below it expecting to be reached. The control bar's **Text Prompts** switch (`'pin prompts'`, key P, `pinPrompts` in config — **on by default**, so the lab opens pinned and hover mode is what the switch turns *on* when it is off) leaves hover mode: `applyPromptMode()` sets `.is-pinned-prompts` on the wrapper, which is what `interactive.css` reads to turn the tooltip card back into the chip with leader and pin, and `updateLabels()` then takes a **second early return** into `updateLabelsPinned()` — a nameplate, not a solved layout. Each chip stands straight above its rig's **root joint, live** (`rootJoint`, the bone with no bone parent — the tree's root node, even a zero-offset armature root; with several trees, the largest), at a fixed **world** height per rig (`labelLift`: the 85th-percentile root-to-mesh-top gap over the sampled frames, `rootGaps` — a percentile so one wingtip at the top of a beat doesn't set the height — plus `LIFT_AIR` of air that is one world distance per stage (`stageLiftAir`, scaled by the stage's `scale`), not a fraction of the rig — root-relative because the chip rides the root, so a rearing rig doesn't carry it up twice; the distance differs rig to rig), pin on the joint, leader vertical, no collision pass, no slot choice, no easing, no depth grading. Chips may overlap; that is the trade. So **the anchored solver never runs in the lab at all** — it is the project page's alone, and the catalog's `labelSlot`/`labelOffset` mean nothing there. The render tool's `--labels` is this switch turned on at load.

> **Known gap (not implemented).** The pick runs *only* on `pointermove`, but rigs walk and auto orbit sweeps the stage past a still cursor, so the prompt goes stale until the pointer moves again. Fixing it means driving the pick from the render loop with some hysteresis, testing against `localBoxFull` (it spans every frame, so it covers a travelling rig's whole corridor).

**The lab's phone console** (`interactive.css` ≤560px): the control bar and the dock are separate absolutely-positioned elements that FUSE into one plate **by arithmetic** — the bar is border 1 + readout 34 + rule 1 + two switch rows (2×2, four switches) 88 = 124px tall, and the dock hangs at top +123, one px under it. Change any row height and move the dock's offset with it, or the plate splits. Between 561–900px the dock is instead a corner pill (top-left, mirroring the bar top-right) — never give it back a fixed vertical offset, which is what used to land it on the category strip in landscape.

**The stage rail** is a **ruled register** — full-bleed rows with a hairline above each, which is what keeps a row from reading as a prompt chip. It replaced a sheet of framed cells that read as an unfinished table. The selected row's plate is drawn by **`::before` inset inside the row, never a border or margin**, both of which change the row's main-axis size and would re-cut all sixteen lines on every selection. Below 720px it becomes a horizontal strip and **keeps the pill** — none of the register survives being laid on its side.

**Galleries and TOC**: `gallery.js` navigates by *live* item position (a video's intrinsic size isn't known early), plays only on-screen clips, and gives the three **Application clips only** a π0.5-style control bar — the Experiments strips are comparison figures and chrome on six clips at once is noise. Full screen goes on the **container**, not the video, so the bar stays usable. Scroll targets are **left-aligned, not centred** (centring the middle of three would cut both neighbours in half). Auto-cycling strips always yield to the visitor, and the yield signal is the container's own `scroll`, not `wheel`/`touchstart`, which also fire when merely scrolling the page past the gallery.

**`unimate/tools/`** is the one directory here that is **not shipped** — `render-category.mjs` renders a lab category to a video offline (Node + Chrome over CDP + ffmpeg, no npm), and since 2026-09-12 the homepage's two thumbnails too (`--lab`, adapters in `lib/labs.mjs`). It drives the real page rather than reproducing it, so stage framing is still only `examples.js`/`stage-tuning.js`, and it reaches the page through `Page.addScriptToEvaluateOnNewDocument` alone: **never add a capture-only branch to the shipped viewer** (the overview labs' `maxPixelRatio` is a config knob, read where the cap already was). The entry file is the sequence only; each step is a module in `tools/lib/` (mapped in the README). `lib/bootstrap.mjs` is the exception to the module style — it is **stringified into the page**, so it takes no imports and nothing it needs may leak into the shipped viewer. Its renders land in `~/Downloads/lab_renders/`, outside the repo, because every file under `assets/**` is referenced. ## Verification gotchas

An automated tab often isn't painting, so **`IntersectionObserver` never fires there** — below-fold sections look stuck until the 3s failsafe, and gallery clips won't autoplay. A synthetic click carries no user activation, so `requestFullscreen` can reject. For the nav keypoint, read `getAnimations()[0].effect.getKeyframes()` rather than sampling `getComputedStyle().transform`, which sits frozen at the start value and looks like a bug that isn't there. In all three cases: the harness, not the code.

When no browser is attached, `unimate/tools/render-category.mjs` is the way to *see* a lab stage: it drives the real page headlessly, so `-c <slug> --seconds 0.1 --scale 1 --chrome-ui --labels -o <dir>/x.png` writes real frames of the stage with its rail, count and chips. It renders the lab only — the embedded viewer on the project page has no headless path.

**A stylesheet that silently lost rules is the failure mode to check for after editing comments** — one unterminated `/*` swallows everything to the next `*/`. Two cheap gates, no tooling required: brace and `/*`…`*/` counts must balance per file, and in the page `[...document.styleSheets].map(s => [s.href, s.cssRules.length])` must show every sheet with a plausible rule count (a swallowed section shows up as a short one). `xmllint --noout sitemap.xml` and `node --check` on each `.js` cover the other two file types.
